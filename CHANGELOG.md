# Changelog

All notable changes to Pergamum will be documented in this file.

## [0.1.19] - 2026-09-15

- **Fixed: two different books with the same title were merged into one.** Book identity was the title slug alone, so a CSV row for José Enrique Rodó's *Ariel* found Sylvia Plath's, attached Rodó and his translator to her book as co-authors, and filed the copy underneath. Identity is now **same title *and* at least one author in common** — `App\Support\BookMatcher`, the one place the rule lives. Different authors → a different book; a shared author → the same book, so a later edition that adds a foreword writer or translator gains a co-author rather than a duplicate. The importer resolves through it; `POST /create-book/title` (which has no authors yet) now returns every same-title book *with its authors* as `matches`, and the confirmation screen lists them — "Add a version" per book, or "Create a different book".
- **New slug rule for a title clash.** The first book with a title keeps the bare slug; a second is filed under the title plus its primary author's surname (`ariel-rodo`), and only a third by a same-surname author gets a number. Every create door passes its authors to `BookCreator::create`. Renaming keeps a disambiguated slug when the new title slugs to the same base (so `ariel-rodo` can't collapse back onto `ariel`) and otherwise re-derives it collision-free.
- **`php artisan book:split`** pulls a wrongly merged book back out: name the copies (`--copy`), authors and genres that belong to the other book, and it creates that book with a proper slug, moves them across (read history follows its copy for every account; list items and shelf locations need nothing), and refuses to leave the original empty. `--dry-run` prints the plan. Plath's and Rodó's *Ariel* have been split.
- The importer's `ambiguous_copy` guard keys on `(title, primary author, format, nickname)` now, so two same-title books by different authors on two shelves are two copies, not a collision.
- 24 new backend tests (`BookIdentityTest`, `SplitBookCommandTest`, and identity cases on the bulk-upload, new-book, book-update and location suites); `NewBookStore` spec updated for `matches`.

## [0.1.18] - 2026-09-15

- **Fixed: a location page listed one row per book, not per copy.** `GET /locations/{location}/books` inherited `BookListing`'s book-level shape, so a shelf holding two copies of one novel showed one row under a header saying "22 copies" — and, worse, that row's format and page count came from `versions[0]`, the book's *oldest* version, which could be an audiobook shelved nowhere near the page you were on. The listing now loads only the subtree's copies (in shelf order) and flattens each book to one row per copy carrying just that copy, so the table and the header count agree and every row shows the copy that is actually there. Pagination is still by book; a page holds at least `limit` rows.
- `BookshelfTable` / `BookTableRow` grew a `per-copy` prop: rows key on the version rather than the book (the same book can now legitimately appear twice) and show the copy's nickname under the title, which is what tells two copies apart. Off by default — the library and genre pages are unchanged.
- **The home page version follows the changelog.** `HomeView` had `v 0.1.6` hardcoded twelve releases ago. `vite.config.js` now reads the newest `## [x.y.z]` heading from `CHANGELOG.md` at build time (`utils/changelogVersion.js`, unit-tested) and injects it as `__APP_VERSION__`; adding a changelog entry is the whole release-bump step.
- Not changed: location **statistics** still count `totalItems` as distinct books ("Books Here"), matching lists — 21 books, 22 copies, on a shelf like that is the intended reading, and "Total Pages (all copies)" is the copy-level figure.

## [0.1.17] - 2026-08-22

- **Physical shelving is a first-class concept.** A new self-referencing `locations` table (room → bookcase → shelf, `kind` an open vocabulary) and a nullable `versions.location_id` + `shelf_ordinal` replace the convention of encoding shelves as lists. A copy is in exactly one place, and that is now a database fact — the old `list_items` shape could never enforce it. A backfill migration parsed the 16 `O1S5`-style shelf lists into 3 rooms, 5 bookcases and 16 shelves and pointed all 465 versions at their shelves, ordinals included; **the shelf lists were deliberately not dropped** and remain as recoverable backup until the location UI is trusted.
- **New API surface** (`auth:sanctum`): `apiResource /locations` (slug-routed, unlike genres), `GET /locations/{location}/books` (paginated subtree listing built on `App\Support\BookListing`, with a new `shelf` left-to-right sort that is a shelf page's default), and `PATCH /versions/{version}/location` to shelve/move/unshelve one copy. `LocationService` owns code identity, the move-cycle guard, and deletion semantics: a location with child locations always refuses deletion, one with shelved copies refuses without `?force=true`, and force means "unshelve", never "delete copies". Discarding a copy now clears its shelf; restoring does not reshelve.
- **Statistics gained a `location` scope** — one scope whose subtree width does the work, so `/api/statistics/location/o1s5`, `…/o1` and `…/o` (shelf, bookcase, room) all answer with the same seven metrics (`totalItems`, `totalPages`, `completedCount`, `completedPercent`, `genreBreakdown`, `averageRating`, `ratingDistribution`). The items-shaped metrics now dispatch through `Support\ScopeQuery` (list vs location) rather than hardcoding `ListQuery`.
- **The CSV contract gained a `location` column** (`CODE` or `CODE|ordinal`), applied on version create only — a re-import can't reshelve a copy you moved — and exported for every shelved copy, so a database reset no longer silently loses the physical layout. Unknown codes fail the row (`location_not_found`) so a typo can't invent a shelf; the reset case, where `migrate:fresh` has emptied `locations`, opts in with a new `create_locations` upload flag that rebuilds each shelf code's room → bookcase → shelf chain. Two rows sharing `(title, format, nickname)` but naming different shelves are two copies the version dedupe would collapse — the later row now fails (`ambiguous_copy`).
- **SPA**: a Locations section (tree browse at `/locations`, per-location page with breadcrumb, child chips and the subtree's books, statistics at `/locations/:slug/statistics`), a Location column with a Shelve/Move picker on the book page's version table, a sidebar link, and an `/admin/locations` screen — the tree with per-row Edit / Move / Add child / Delete, where Move's parent select excludes the row's own subtree and Delete is the genres' two-step shape (the server reports what's in the way; shelved copies escalate to an acknowledged unshelve-and-delete, child locations are a hard stop). `LocationsStore` fetches the ~24-row tree once and refetches after every mutation, GenreStore-style.
- Deliberately **not** in the book create/edit payloads: shelving has exactly one write path (the version-location endpoint), rather than becoming a fifth field four ingest doors must keep agreeing on. Copies created through forms land unshelved and are placed from the book page. See `/documentation/locations.md`; follow-ups (shelf-list deletion, reorder UI, capacity) in `/feature-plans/locations.md`.
- **Books can be shelved from the shelf page.** The list page's "Add a book" widget (title search → pick a version) is now a shared `AddBookSearch` component used by both `ListView` and `LocationView`; on a leaf location it shelves the chosen copy to that location via the same `PATCH /versions/{version}/location` write path, with already-shelved-here copies shown disabled. Same data shape throughout — this is a second door to an existing endpoint, not a new one.
- 43 new backend tests (locations CRUD + books listing, shelving + discard interplay, backfill migration, CSV column + `create_locations` + wipe-and-recover round-trip, location metrics) and a `LocationsStore` spec; the export-header contract test moved with the contract.

## [0.1.16] - 2026-08-19

- **Fixed: the genre page ordered its books by an author it never showed.** `GenreController::show` still ranked books by `MIN(authors.last_name)` — the author whose name sorts first alphabetically — while the column above them is headed "Primary Author" and renders `authors[0]`. A book credited to Vance and Anderson filed under A and displayed Vance, so the page looked unsorted next to the library, which has ordered on the primary author (lowest `author_ordinal`) since 0.1.12.
- **Both listings now build the same query.** `BookController::libraryQuery()` and its sort applier moved to `App\Support\BookListing` — `SORTABLE`, the per-column correlated subqueries, the absent-values-last rule, and the `books.book_id` tiebreak. `BookController::index` reads `?sort=` / `?direction=` off the request; `GenreController::show` builds on the same query and takes the default. A new book listing should call it rather than growing a third variant, which is exactly how the genre page drifted.
- **Three more things came with the shared query.** Genre pages now eager-load authors in `author_ordinal` order, versions by `version_id` and reads newest-first, so the author, format, page count and date each row renders is the one the ordering used. Ties break on the primary key, so paging through a genre where every book files under the same name can no longer repeat or drop a row. And the raw `leftJoin('read_instances', …)` is gone — it sat outside `BelongsToCurrentUser`'s reach, the last place in the app that did.
- Not changed: `GET /genres/{genre}` still takes no `?sort=`, and `GenreView`'s table headers stay inert. The endpoint is one passthrough away from accepting it now; the remaining work is the URL handling `LibraryView` already models, tracked in `/feature-plans/books.md`.
- `tests/Feature/Genres/GenreBooksOrderingTest` pins the ordering, the eager-load order, the pagination tiebreak and the user scoping (9 tests).

## [0.1.15] - 2026-08-19

- **The genre index is one page again.** `GenresView` paginated 142 genres at 25 a page — six clicks over a list that fits on one screen, with the longest name in the catalog at 23 characters. It now renders the whole catalog as a responsive card grid, grouped under sticky letter headings with an A–Z jump rail, and `books_count` is drawn as a bar beside the number rather than parenthesised after the name.
- **Fixed: the search box could take the page down.** The filter built `new RegExp(searchTerm, "i")` from raw input, so a lone `(` threw a `SyntaxError` out of a computed mid-keystroke and left the view blank until a reload. Filtering is a lowercased `includes` now, in one place both search boxes call.
- **Fixed: searching from page 2 or later found nothing.** `currentPage` lived on `GenreStore` and never reset when the term changed, so filtering to three matches while on page four sliced an empty window — and because it was *store* state, navigating away and back returned you to page four of a list you'd stopped looking at. Pagination is gone and `currentPage` with it.
- **Fixed: the first click on "Name" sorted Z→A**, because the toggle treated the initial `null` state as though it were already ascending, and both sort arrows pointed the opposite way to the order they described. Sort is now a two-state toggle whose labels — "A–Z" and "Most books" — state the direction outright, so there's no arrow to get backwards.
- **The index has loading, error, and empty states** for the first time. `mounted()` called `getAllGenres` directly and didn't catch, so a failed request left a permanently blank list with no explanation; it goes through `GenreStore.fetchAllGenres({ force: true })` and renders `PageLoadingIndicator` / `AlertBox` like every sibling view. It also links to `/admin/genres`, which until now was reachable only by typing the URL.
- **Counts are sized on a square-root scale, against the full list rather than the filtered one.** The distribution is severely long-tailed — nonfiction holds 383 books, 39 genres hold exactly one — so linear bars would flatten the entire tail into an identical sliver, and a font-size tag cloud would encode data as type size and make most of the page unreadable. Scaling against the whole list is what stops bars rescaling under the user while they type.
- **The list-shaping rules moved to `resources/js/utils/genreList.js`** — `filterGenres`, `sortGenres`, `groupByLetter`, `countScale` — pure, and unit-tested in `resources/js/tests/utils/genreList.test.js` (21 tests). The suite still has no component-test tooling (`/feature-plans/frontend-tests.md`), so extracting the logic is the only way to pin any of it. `/admin/genres` now shares `filterGenres`; it deliberately doesn't share the sort or the grouping, since every row there carries actions and section headings would only get in the way.
- Not changed: `GET /genres` is still "everything, alphabetical" with no `?q=` and no server-side pagination, so this is client-side and stays viable into the low thousands of genres — the grid gives out before the fetch does. Logged in `/feature-plans/genres.md`.

## [0.1.14] - 2026-08-19

- **An author now needs a first name *or* a last name, not both.** All three book requests required `last_name` outright, so Plato, Aristotle and National Geographic could not be created through the app at all — and, worse, any book they were already on failed validation on save, because the edit form round-trips its existing authors back into the payload. They got into the catalog through the CSV importer, which has always asked only that one half be non-empty. The importer's rule was the right one; it is now everyone's.
- **The rule is stated once,** in `App\Http\Requests\Concerns\ValidatesAuthorNames` — rules, message, `author_name_required` reason code, and a normalize-before-validate pass so a whitespace-only name is the absence it looks like. `StoreBookRequest`, `UpdateBookRequest` and `CompleteBookCreationRequest` compose it; `resources/js/utils/validators.js` mirrors it client-side, and the three forms' "Last name is required." now reads "Enter a first or last name."
- **Author resolution was duplicated four ways; it is now `AuthorService`.** `BookController::handleAuthors`, `BookController::updateAuthors`, `NewBookController::handleAuthors` and `BulkImportService::attachAuthors` each had their own find-or-create — which is how the validation rules drifted apart in the first place. They all call `AuthorService::resolve()` / `attachToBook()` / `rename()` now, so `normalize()` and `slugFor()` are the only spelling rules in the application. Same shape as the `GenreService` consolidation in 0.1.10, and the plan `/feature-plans/bulk-upload.md` had been carrying. `tests/Feature/Authors/AuthorIngestTest` pins all four doors against one set of rules.
- **Consolidating adopted the importer's attach semantics, which fixes co-author ordering.** The three form doors called `$book->authors()->attach($ids)` with no pivot data, so every author on a book created or edited through a form sat at the `author_ordinal` column default of 1 — and `authors[0]`, the name every book row renders and the library sorts on, was whatever the database handed back first. Co-authors are now numbered in input order, and a re-attach is a no-op.
- **`author_ordinal` is declared on the relation** (`Book::authors()`, `Author::books()`). It was written but never loaded, so `CatalogExportService::authorField` sorted the export's author list on a `null` pivot value for every row — its `?? PHP_INT_MAX` fallback made the sort a silent no-op.
- **Matching is on the slug alone.** The old `firstOrCreate(['slug', 'first_name', 'last_name'])` matched on all three, so a differently-cased first name missed the existing row and then tried to insert a duplicate slug — a `QueryException` since the unique index landed, not a second author.
- **Fixed: `BookCreateEditForm` validated authors and versions and then ignored the answer.** `validateBook` computed all three sections, wrote them to `isValid` for the template, and returned only `Object.values(isValid.book).every(...)` — so an invalid author or version rendered its error message *and* submitted, leaving the API's 422 as the only thing stopping it. It now returns the conjunction of all three.
- **Two bugs that had been hiding behind that.** Audio runtime was checked with `validateNumber`, but its input is `type="text"`, so every filled audiobook was invalid — turning the gate on without this would have blocked them outright. Page count already allowed for the string; the two now share `validateVersionLength` in `utils/validators.js` so they can't diverge again. And the author validity array was pushed as `{ last_name: true }` in two places (both marked `// BUGGY!`) while the template tests `!isValid.authors[idx]` — an object is truthy, so those rows could never show an error. `formatBookToEdit` also pushed onto the default arrays instead of replacing them, leaving `isValid` one entry longer than the form and every message pointing at its neighbour.
- Not changed: `AuthorController::getOrSetToBeCreatedAuthorsByName` still derives its slug from the joined `name` rather than the two parts. It has no live caller and its fate is an open item in `/feature-plans/authors.md`. Renaming an author still leaves `authors.slug` on the old spelling, for the same reason it always did — re-slugging can collide with the unique index. Both are logged there.

## [0.1.13] - 2026-08-19

- **Fixed: single-name authors no longer clump at the top of the library.** Sorting by Primary Author ordered on `authors.last_name`, and mononyms and organizations — Plato, Aristotle, National Geographic — are stored the way they read, with a first name and an empty last name. Every one of them filed under `''`, so they all landed ahead of A, ordered among themselves by nothing visible (the tiebreak fell through to `book_id`). They now file under their single name: Aristotle sits between Arendt and Armstrong.
- **The rule lives in `Author::sortNameExpression()`** — `coalesce(nullif(trim(authors.last_name), ''), authors.first_name)` — used by `BookController::libraryQuery` (both the `sort_author` value and the tiebreak that picks which author it comes from) and by `GenreController::show`, which had the same `MIN(authors.last_name)` ordering. Any future author-ordered listing should call it rather than ordering on `last_name`.
- **No data moved.** Rewriting single names into `last_name` would produce the same ordering by recording "Plato" as a surname, which is wrong everywhere the two columns are read apart — edit forms, imports, and the "First Last" display. Whitespace-only last names count as absent for the same reason, so a stray space from an import doesn't sort ahead of every real name.
- Three tests in `LibrarySortingTest` cover it: mononyms interleaving with surnames, whitespace-as-absent, and a mononym primary author still outranking an alphabetically-earlier co-author.

## [0.1.12] - 2026-08-09

- **New: the library table sorts.** Clicking Title, Primary Author, Format, Page Count, Date Read or Rating reorders the whole library; clicking the active column flips direction. `GET /books` gained `?sort=` (`title`, `author`, `format`, `pages`, `date_read`, `rating`) and `?direction=` (`asc`/`desc`), both whitelisted and both falling back to the default on anything unrecognized rather than 422-ing a stale bookmark. Genres has no sort — a row shows up to two of them, so there is no single value to order on.
- **Sorting is server-side, deliberately.** The listing is paginated at 20, so a client-side sort could only ever reorder the page already fetched — "highest rated" would mean "highest rated of these twenty". The `sortedBy` state and `sortedBooks` getter in `BooksStore` (and `sortedBy` in `AuthorsStore`) were the beginning of the client-side version; they were never wired to anything and are gone.
- **`BookController::index` was rebuilt on correlated subqueries instead of joins.** The old shape left-joined `book_author`, `authors` and `read_instances`, then collapsed the row explosion with `MIN(authors.last_name)` + a manual `GROUP BY` — which meant every column added to the `select` had to join the `GROUP BY` too, a standing break under MySQL 8's `ONLY_FULL_GROUP_BY`. One subquery per sortable column produces one row per book to begin with, so there is nothing to group.
- **That fixes a user-scoping bug as a side effect.** The `leftJoin('read_instances', …)` was raw, and `BelongsToCurrentUser` constrains a model's own queries rather than a join against its table — so it saw every account's reads. The replacement subqueries are Eloquent builders, so the scope applies inside them. Sorting by date read or rating is only meaningful per-user, which is why the feature and the fix were the same change. `LibrarySortingTest::test_read_derived_sorts_ignore_other_users_reads` pins it.
- **`searchBooks` is gone; `index` handles `?search=` inline.** They were near-duplicate 40-line methods, which is why sort would have had to be implemented twice. Author matching moved from a join to `whereHas` to preserve the one-row-per-book shape. Search, the format filter, the shelf filter and the sort now all compose on one query.
- **Search escapes LIKE wildcards.** `%` and `_` were passed through, so a search for `%` matched every book. Always injection-safe (the term was bound); now it also returns what it looks like it will.
- **Three ordering rules worth knowing.** Books with no value sort last in *both* directions — MySQL puts `NULL` first ascending, which would head a "by rating" list with everything you've never read. `date_read` and `rating` resolve against the most recent read rather than a best or an average. `format`, `pages` and `author` resolve against the first version / lowest `author_ordinal`, and the eager loads are ordered to match, so the value shown in a column is the value sorted on. Ratings are stored doubled and sorted raw — doubling is monotonic, so ordering is unaffected.
- **Sort, search, page and shelf all live in the URL now.** `LibraryView` drives every fetch off `$route.query`, so a sorted view is linkable and survives a refresh, and paging keeps the sort and search it was reached under. Previously the search button ran its own fetch that ignored pagination, so any subsequent navigation silently dropped the search term. Defaults are omitted from the URL, and any of these changing resets to page 1.
- **Pagination gained a PK tiebreak.** No sort key is unique, and paginating a non-unique ordering lets rows repeat across pages or vanish between them — 250-page books were the obvious case.
- Fixed: `BookshelfTable` keyed its rows on `book.book_id`, which is one level too shallow for the payload shape (`{ book: { book_id } }`) — every key was `undefined`. Same class of bug as the `FormatsList` one in 0.1.9. Its header spans also stopped being string-interpolated into `col-span-${n}`, which Tailwind's scanner can't see.
- Removed the unused `sortablejs` drag-to-reorder block from `BookshelfTable` — no view ever passed `isSortable`, and it emitted the *unsorted* array anyway, since sortablejs mutates the DOM rather than the bound list. The two packages are still in `package.json` with no importer; logged in `/feature-plans/books.md`.
- `tests/Feature/Books/LibrarySortingTest.php` (16 tests) covers each sort key, both directions, nulls-last, primary-vs-alphabetical author, latest-vs-best rating, cross-user isolation, composition with search and the shelf filter, tiebreak stability across pages, and wildcard escaping.
- **Only the library sorts.** `AuthorView`, `GenreView`, `FormatView`, `CompletedView` and `ListStatisticsView` render the same table with inert headers — they don't fetch through `GET /books`, and each backing endpoint needs the same two parameters first. Tracked as item 5 of `/feature-plans/books.md`.

## [0.1.11] - 2026-08-09

- **Fixed: saving the book edit form 422'd on any book rated above 2.5 stars.** `PATCH /api/books/{id}` came back `rating_out_of_range` — "rating '6' must be between 0.5 and 5 in 0.5 steps" — because the form was round-tripping the storage scale. Ratings are stored doubled to fit an integer column, the show payload carried the doubled value, and `EditBookView` compensated by doubling its `<option>` values too, so a 3-star read submitted a `6` into a rule that validates the 0.5–5 display scale.
- **`ReadInstance` now has a `getRatingAttribute` that halves on read**, closing the mutator-without-accessor asymmetry that `/feature-plans/books.md` had flagged as a recurring source of bugs. Every Eloquent path — book show, list payloads, the CSV export — now emits the display scale, so the ad-hoc `/ 2` in `BookView`, `BookTableRow` and `CatalogExportService::ratingField` is gone. The doubling itself is unchanged and no data moves; only what crosses the wire changes, from `10` to `5`.
- Two paths deliberately still convert by hand and say so in comments: `AverageRating`, because `avg()` passes through to the query builder and never hydrates a model, and anything using `DB::table()`. `RatingDistribution` does hydrate, so it stopped dividing.
- API consumers other than the SPA should note the wire-format change on `read_instances.rating`. Writes were always on the display scale and are unaffected.

## [0.1.10] - 2026-08-09

- **All four genre-ingest paths now go through `GenreService`.** `BookController::handleGenres`, `::updateGenres` and `NewBookController::handleGenres` each called `Genre::firstOrCreate` with whatever the caller typed, so `GenreService::normalize` applied to the admin door only and the same genre could arrive spelled three ways. They are replaced by `GenreService::attachByName()` (the create doors) and `::syncFromInput()` (the edit door). The input shapes still differ — consolidating those needs the create endpoints merged first — but the resulting rows no longer do.
- **The plans had counted three ingest paths; there were four.** `BulkImportService::attachGenres` matched on `LOWER(TRIM(name))`, which trims but does not collapse internal whitespace — so `science  fiction` imported from a CSV was a *different row* from the one the book form would have created, and no index could serve the lookup. It now calls `attachByName` like everything else. `BulkImportService` gained a constructor for the dependency.
- **Behavior change: a blank genre name is dropped rather than rejected or stored.** `book.book.genres.parsed.*` and `bookData.genres.*.name` became `nullable`. Previously the create door **422'd the entire book** if any genre slot was empty: `ConvertEmptyStringsToNull` rewrites `""` to `null` before validation, and the `string` rule then failed on it. The SPA filters empties before sending, so this never fired in the app — it was waiting for any other client. The admin CRUD door still returns 422 for a blank name, which is intentional: an empty row in a book form is a form artifact, a genre named four spaces is a mistake.
- **Payload-level dedupe is now explicit.** Two new spellings of the same genre in one request (`Fantasy` / ` fantasy `) never reach the database to be compared, so the `utf8mb4_unicode_ci` collation can't merge them the way it merges a new name against an existing row. `GenreService` lowercases in PHP to close that.
- **A `genre_id` on the edit door beats the name arriving beside it.** Unchanged behavior, now stated: the edit form renders the stored name into a text input, so an edited name next to an existing id is a rename, and renaming is `GenreService::rename()`'s job — it checks for conflicts the ingest path cannot. An id that no longer resolves falls back to the name.
- **New migration: a unique index on `genres.name`** (`2026_08_09_000000`), which is what actually closes the select-then-insert race that `findConflict` and `firstOrCreate` both have. **It has not been run against live data and will refuse to.** `up()` counts duplicate names first and throws listing every offender with a pointer to `/admin/genres`, rather than letting MySQL fail on one row and leave the rest to be found by hand. Merge the duplicates, then migrate. Under `utf8mb4_unicode_ci` the index is case-insensitive, which is the intent.
- **New: CI.** `.github/workflows/ci.yml` runs `pint --test` + `phpunit` against a `mysql:8` service, and eslint + `vitest run` + a production build, on every push to `main` and every PR. Nothing ran the suites automatically before. New `npm run test:run` script — `npm test` stays in watch mode for local work.
- `tests/Feature/Genres/GenreIngestTest` (18 tests) pins the four doors in parallel, and `tests/Feature/Migrations/AddUniqueIndexToGenresNameTest` covers the guard and the index. Note the latter's `tearDown`: MySQL implicitly commits on DDL, so a migration test that drops an index has to restore it by hand or `RefreshDatabase` leaks the missing index into the next test.
- Retired `/feature-plans/backend-tests.md`. Its one open item (wire CI) is built, and its known limitations were accepted trade-offs rather than future work — the MySQL-over-sqlite rationale, the breadth-first coverage shape, and the no-snapshots rule now live in `/documentation/backend-tests.md` where someone writing a test will actually be.

## [0.1.9] - 2026-08-04

- **New: genres have a real CRUD surface at `/admin/genres`** — create, rename, delete, and merge. Genres were previously only ever created as a side effect of book creation (`Genre::firstOrCreate`), and the only way to fix one was direct SQL against `genres` and `book_genre`. The motivating case is loose data entry producing near-duplicates (`essay` / `essays`, `sci-fi` / `scifi`), which the surface handles from both directions: merge folds N strays into one canonical genre, and rename reports a collision instead of creating a second row sharing a name.
- **New endpoints:** `POST /api/genres`, `PATCH|PUT /api/genres/{genre}`, `DELETE /api/genres/{genre}`, and `POST /api/genres/{genre}/merge` (where `{genre}` is the winner and the body carries `source_ids`). `GenreController::store`, `update` and `destroy` had been registered-but-empty stubs returning `200` with no body and no side effect — worse than a 404, because it implied the operation succeeded. `GenreService` now owns the name rules and `GenrePolicy` the (currently permissive) authorization.
- **Breaking-ish: `Route::resource('/genres')` became `Route::apiResource`.** The `genres.create` and `genres.edit` HTML-form routes are gone; they only ever pointed at empty methods. `GenreController::show` also moved from a raw `$genre_id` + `findOrFail` to route-model binding, which is the same 404 by a different path.
- **A name conflict is a `409` carrying the colliding genre, not a `422` from `Rule::unique`.** Deliberate: a validation failure can carry a message but not the conflicting row's `genre_id`, and the SPA needs that id to offer "merge into it instead" without a second round-trip. Callers should key on `reason_code` (`genre_name_taken`, `genre_in_use`) rather than the status family. The match is case- and trailing-space-insensitive, which the `utf8mb4_unicode_ci` collation provides for free — and which `GenresCrudTest` now pins, since nothing in PHP enforces it.
- **Deleting a genre that books use requires `?force=true`.** An unforced `DELETE` answers `409 genre_in_use` with the book count, so the SPA can state the impact before asking; re-sending with `force` goes through. Deleting is allowed on purpose — stripping a junk tag off forty books shouldn't need a merge-into-nothing workaround — but the unforced request is a server-side backstop so a mis-wired button can't do it silently.
- **Merge attaches the difference and then deletes the losers; it does not `UPDATE book_genre SET genre_id`.** The pivot has no unique constraint on `(book_id, genre_id)`, so the naive update would leave a book tagged with *both* the winner and a loser holding two pivot rows for the winner. That duplicate is invisible in `GenreBreakdown` (it counts `DISTINCT book_id`) but over-reports in the `withCount('books')` the admin screen displays — silent drift, of exactly the kind this feature exists to remove. `GenreMergeTest::test_a_book_tagged_with_both_winner_and_loser_keeps_exactly_one_pivot_row` is the guard.
- **The three book-ingest paths are deliberately untouched.** `BookController::handleGenres`, `::updateGenres` and `NewBookController::handleGenres` still call `Genre::firstOrCreate` directly, so `GenreService`'s normalization applies to the admin door only. Consolidating them is a book-pipeline change with a much larger blast radius; the service is shaped so `attachByName()` drops in later without moving the name rules again.
- **The unique index on `genres.name` has not landed.** It can't run against a database that still holds duplicates, so it ships only after merge has been used against the live data. Tracked as item 1 of `/feature-plans/genre-management.md`.
- **Admin shell: `AdminHome` derives its menu from the route table.** A route declaring `meta.adminMenu: { title, description }` appears on the landing page automatically — adding an action is no longer a three-step ritual with a link that's easy to forget. `AdminActionView`'s `components` map switched to `defineAsyncComponent`, so each action loads its own chunk instead of every action being bundled into the admin route.
- New `resources/js/components/globals/ConfirmAction.vue` — the shared destructive-action confirm, taking a concrete `impact` string rather than a bare "are you sure?". Genre delete and genre merge are its first two consumers; book delete and the eventual author merge are why it lives in `globals/`.
- `GenreStore` gained `fetchAllGenres({ force })` and the four mutations, each of which **refetches** the list rather than patching it — a merge changes `books_count` on rows it never named and deletes others outright, and the same array backs `GenresView` and `GenreTagInput`'s autocomplete.
- Fixed: `FormatsList` keyed its rows on `format.id`, which has never been a column — every key was `undefined` and Vue fell back to index-based diffing.

## [0.1.8] - 2026-08-04

- **Read history is user-scoped by the model rather than by every reader.** `App\Models\Scopes\BelongsToCurrentUser` is a global scope on `ReadInstance`: `where('read_instances.user_id', auth()->id())` is now what happens unless a caller opts out by name. It replaces fifteen hand-written predicates across `BookController`, `BookService`, `ListController` and the statistics layer.
- **Fixed: the author and genre detail pages leaked read history across accounts.** `AuthorService::getAuthorWithRelations` and `GenreController::show` both eager-loaded `books.readInstances` with no user filter — the two readers that forgot the predicate every other reader remembered. Both are closed by the scope, and pinned by `tests/Feature/UserScoping/TaxonomyScopingTest`.
- Querying `ReadInstance` with no authenticated session now throws instead of guessing. Matching nothing would make a console context look like an empty library and matching everything would silently undo the scope; a caller that means it writes `withoutGlobalScope(BelongsToCurrentUser::class)`.
- Three call sites lift the scope deliberately: `BookController::destroy` (deleting a book must remove *every* account's reads of it, or they orphan against a deleted `book_id`), and `ReadInstanceQuery::forScope` / `TotalBooksRead` (statistics answer for the scope's subject, not the session — so an admin scope reporting on another account still works).
- `BookList` deliberately did **not** get the scope. It would run before `BookListPolicy`, so route model binding would fail to resolve another user's list and every documented 403 would become a 404.
- **New: `GET /api/export` returns the catalog as a CSV the bulk importer reads back.** Streamed, one row per (version, read), with a "Download export" button on `/bulk-upload`. The catalog crosses whole; read history and lists are the requesting user's only. `rating` is halved back to the 0–5 display scale, without which a roundtrip would double it on every pass.
- **The CSV contract gained three optional columns** — `is_discarded`, `discarded_at`, and `lists` (`;`-separated `Name|ordinal`). Every file that was valid before still is. Discard state and list membership were both silently lost by a database reset: the first has been un-roundtrippable since discarding shipped in 0.1.3, and the second since lists existed. The ordinal travels in the cell because row order cannot carry it — a version on two lists sits at a different position in each.
- `App\Support\CsvContract` holds the column vocabulary for both the reader and the writer, so a column added to one and forgotten by the other can't quietly stop surviving a reset. `tests/Feature/Export/CatalogRoundtripTest` exports a catalog exercising every column, wipes everything but formats and users, re-imports, and asserts equality.
- Retired `/feature-plans/reset-database.md`. Its runbook is now `/documentation/database-reset.md`, its export wish is built, and both of its known limitations are gone: lists roundtrip, and `Book.nickname` turned out never to have existed as a column — only `versions.nickname` does. Same class of error as the `date_completed` accessor removed in 0.1.7.

## [0.1.7] - 2026-08-03

- The book write surface validates its input. `BookController` and `NewBookController` called `validate()` zero times between them and reached into payloads by key, so a missing key was an `Undefined array key` — a 500 that told the caller nothing. Every write endpoint now takes a `FormRequest` under `app/Http/Requests/`: `StoreBookRequest`, `UpdateBookRequest`, `StoreReadInstanceRequest`, `StoreVersionRequest`, `CreateBookTitleRequest`, `CompleteBookCreationRequest`, plus `StoreListRequest`, `UpdateListRequest`, `StoreListItemRequest` and `ReorderListRequest`. They share `ApiFormRequest`, which keeps the API's `reason_code` on a 422 now that the checks are validation rules rather than hand-rolled branches.
- **Breaking: `PUT|PATCH /api/books/{id}` takes a flat payload.** `book`, `authors`, `genres`, `versions` and `readInstances` are top-level keys; the `{ request: { formData: … } }` envelope is gone.
- **Breaking: a bad field in a request body is a 422, not a 404.** `POST /add-read-instance` with an unknown `book_id` or `version_id` used to `findOrFail` into a 404. 404 now means the URL's resource is missing.
- **Breaking: `POST /api/create-book` reports failure with a failure status.** A malformed payload is a 422; an unexpected error is a 500. It used to answer `200 { success: false }`, which a caller had to read the body to notice.
- **Fixed: an unknown format id was silently swallowed on two paths.** `prepareVersions` hit `continue` on a format it couldn't find, so `POST /books` with a typo'd format answered 200 and created a book with no copies; `updateVersions` did the same, so the edit reported success and changed nothing. Both are now a 422 naming the field.
- **Fixed: `POST /api/versions` and `POST /api/create-book` ignored format capability flags.** Only book create and book edit ever applied them, so those two paths could store a page count on an audiobook or a runtime on a paperback — the exact orphan values `estimatedTotalPagesByYear` and `audioRuntimeByYear` double-count. The reduction moved from a private controller method to `Format::lengthFieldsFrom()` and all four writers share it.
- **Fixed: a `date_read` in `m/d/Y` was a 500.** The controllers called `Carbon::createFromFormat('Y-m-d', …)`, which throws on the display format the edit form round-trips. Dates normalize to `Y-m-d` at the request boundary and controllers no longer parse them.
- `POST /add-read-instance` is one insert in a transaction instead of a save through both the book and the version relation, closing the window where the first had landed and the second hadn't.
- Reorder rejections name the offending list-item ids — both the ones that aren't in the list and the ones left out of the payload. Reordering a list you don't own is now a 403; the membership check used to run first and answer 422, which was itself an answer about a list you can't see.
- The book update path and `completeBookCreation` log their exception message and return a generic one instead of putting it in the response body.
- `Book::$fillable` no longer lists `date_completed`, and `getDateCompletedAttribute` is gone. No such column has ever existed; the accessor could only ever return null. Read history is the source of truth for when a book was finished.
- Decided: Pergamum stays a **shared catalog with per-user reading state**. At most one further account is expected and it belongs to the same household, so books, versions, authors and genres stay global and only `ReadInstance` and `BookList` are user-scoped. The "no per-user ownership" entries across six feature plans are closed as deliberate rather than outstanding. Correct `auth()->id()` scoping on reads and lists still matters — that is the only thing separating the two users.

## [0.1.6] - 2026-08-02

- Formats now declare what they are measured in. `formats.expects_page_count` and `formats.expects_audio_runtime` replace every way the app used to identify a medium — `$format->name == 'Audiobook'` / `'Paper'` in `BookController`, `strcasecmp(…, 'Audiobook')` in the bulk importer, `format?.name === "Audiobook"` in two Vue files, and a hardcoded `format_id === 2` in three more. Adding a medium with different length semantics is now a row in `formats`, not a branch. `GET /api/config/formats` carries the two flags, `POST /api/formats` accepts them (defaulting to a print format), and the SPA reads them through `resources/js/utils/formats.js`.
- **Fixed: creating or editing a version of any format other than Audiobook could 500.** The old `'Paper'` branch never matched anything — the format is named "Physical" — so every non-audio format fell through to a branch that read `audio_runtime` unguarded, and a payload omitting it threw `Undefined array key`.
- **Fixed: an audiobook could not be stored without a page count.** `versions.page_count` was `NOT NULL`, so a null page count was an integrity-constraint violation and the importer wrote `0` to work around it. The column is nullable, and a format that carries no page count now stores none. Both read as zero to every `SUM`, so no statistic changed.
- **Fixed: `NewVersionsInput` required a page count for audiobooks**, whose page-count input it doesn't render — an error with nothing on screen to clear it. Validation now follows the format's capabilities, on both the new-version and create/edit forms.
- A length value the format doesn't carry is nulled on write rather than passed through, on every path. Re-formatting an audiobook as physical clears its runtime instead of leaving an orphan that `audioRuntimeByYear` still sums, and an import row can't smuggle a page count onto an audiobook that `estimatedTotalPagesByYear` would then count twice.
- `database/seeders/FormatSeeder.php` (wired into `DatabaseSeeder`) seeds the canonical formats with their capability flags, so `migrate:fresh --seed` produces a database the bulk importer can write to. It `updateOrCreate`s on name, so it also repairs an existing database's flags. This unblocks `/feature-plans/reset-database.md`, whose two largest footgun sections are now moot.
- `ConfigStore.createFormat` refetches the format list instead of pushing the POST response onto it — the two shapes differ, and the forms now read capability flags off whatever is cached.
- Admin format creation gained checkboxes for the two capabilities.

## [0.1.5] - 2026-08-02

- Statistics are now a scoped metric registry (`app/Statistics/`) behind one endpoint: `GET /api/statistics/{scope?}/{scopeId?}`, with `scope` defaulting to `user`, so `GET /api/statistics` still resolves. `?metrics=` takes a comma-separated subset; an unknown key for the scope is a 422, an unknown scope a 404, someone else's list a 403. **Breaking:** the response is now `{ scope, metrics, meta }` with camelCase metric keys throughout — `total_books` → `totalBooks`, `total_books_read` → `totalBooksRead`, `totalPagesByYear` → `pagesReadByYear`, and `booksReadByYear` → `readsByYear`. `App\Services\StatisticsService` is deleted.
- `meta` describes the response's own caveats from declarations on each metric: `catalogWide` (ignores user scoping), `shelfScoped` (excludes fully-discarded books), `estimated` (derived, with the conversion factors echoed), and `failed`. A metric that throws is logged and listed in `meta.failed` instead of 500-ing the whole surface.
- New metrics: `totalReads` (counts undated reads, which the dashboard's client-side sum silently dropped), `uniqueBooksReadByYear`, `averageRating` and `ratingDistribution` (halved to the 0–5 display scale server-side), `audioRuntimeByYear` (minutes), and `estimatedTotalPagesByYear`, which folds listening into pages at a rate configured in `config/statistics.php`. `readsByYear` keeps the old `COUNT(*)` semantics under a label that no longer claims to count books.
- List statistics moved server-side as a `list` scope — `totalItems`, `completedCount`, `completedPercent`, `totalPages`, `genreBreakdown`, `averageRating`, `ratingDistribution`. Every number matches what `ListStatisticsView` used to derive client-side, verified against real data.
- `newestBooks` now excludes books whose every copy is discarded; `totalBooks` deliberately does not, because it is the denominator of `percentageOfBooksRead` and the numerator counts discarded books. The "a book is discarded only when every version is" rule moved from a private controller method to `Book::scopeOnShelf()` / `Book::scopeFullyDiscarded()`.
- `percentageOfBooksRead` no longer re-runs the two counts it depends on.
- Frontend: statistics surfaces are config objects rendered by `StatisticsGrid` over a widget registry. `StatisticsDashboard` and the new `/dashboard` summary are one line each; `/dashboard` stops being a placeholder. A `StatisticsStore` caches per scope and requests only uncached metrics, so `/dashboard` → `/statistics` fetches the delta. Loading, error-with-retry, and empty states now exist on every statistics surface, and `ListStatisticsView` reads the list from `ListsStore` instead of re-fetching it.
- Fixed the `read_instances ⋈ versions` join in the per-year page count, which matched on `version_id` alone and so credited a mismatched historical row to the wrong book's page count.
- Fixed read-history edits silently doing nothing. `ReadInstance::$primaryKey` was `read_instances_id`; the column has always been `read_instance_id`. `PUT /api/books/{id}` filtered incoming read instances on the misspelled key, so every row was discarded before the update ran — changing a rating or a date on the book edit page appeared to save and changed nothing. The model, `BookController::updateReadInstances`, and the edit form now all use `read_instance_id`. Newly created read instances also stop carrying a bogus `read_instances_id` in API responses; no stored data changes and no migration is needed.
